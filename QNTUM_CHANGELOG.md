## QME-PROD-01 — Production-readiness root-cause fixes (Phases 0–6)
- **Branch:** `arena/19807fc5-qntum`.
- **Files:** `Strategy/SignalExpiry.mqh`; `Zones/ZoneEngine.mqh`; `Strategy/MTF/CandidateCollector.mqh`; `Runtime/Engine.mqh`; `Core/Config.mqh`; `QME_Main.mq5`; `Data/DataQualityGuard.mqh`; `Account/SymbolSpecifications.mqh`; `Account/AccountContext.mqh`; `Persistence/PositionStateStore.mqh`; `Persistence/SignalHistoryStore.mqh`; `Runtime/Scanner.mqh`; `Tests/Unit/Test_Expiry.mqh`; `Tests/Unit/Test_Zones.mqh`; `Tests/Unit/Test_Risk.mqh`; `Tests/Integration/Test_MtfPipeline.mqh`; `Tests/Integration/Test_PositionRecovery.mqh`; `test_system.py`; `Documentation/Phase2_3_CodeAndBoundaryAudit.md`; `Documentation/ProductionReadinessChecklist.md`.
- **Changes (Symptom -> Root Cause -> Fix):**
  1. *Cross-symbol signal invalidation:* `CSignalExpiry::Process` checked all signals in `CSignalRegistry` against each symbol's `CZoneEngine`. Fixed by scoping expiry iteration to `zones.Symbol()`.
  2. *Zone engine discarding partial analysis:* `CZoneEngine::Update` exited early on `if(!a.valid)` even after `Scanner` relaxed optional-module completeness. Fixed to require valid `price`, `atr`, and `barTime`, letting each `CZoneBuilder::From*` guard its own optional input.
  3. *Limit orders emitted then hard-blocked at execution:* `CandidateCollector::Collect` emitted `QME_ENTRY_LIMIT` setups when price was outside the zone even though `CExecutionGateway::SupportsEntryType` allows `QME_ENTRY_MARKET` only. Fixed by rejecting non-market entries in `CandidateCollector` so unexecutable limit orders do not consume `m_signalsToday` or fail downstream. Also transitioned deferred signals out of `QME_SIG_APPROVED` in `CEngine::Cycle` when trading is disabled/blocked, and stopped preview mode from burning `m_signalsToday`.
  4. *Notional exposure default blocking 0.01 lots:* `maxSymbolExposurePct=5.0%` / `maxPortfolioExposurePct=12.0%` (and `100.0%` validation ceiling) rejected `0.01`-lot FX/Gold trades on typical `<$22k–$81k` accounts. Fixed by calibrating defaults to `150.0%` / `300.0%` (1.5x / 3.0x leveraged notional) with `(0, 1000.0]` config bounds while keeping all risk-per-trade, daily-loss, drawdown, margin-buffer, and fail-closed safety switches untouched.
  5. *Monday/post-holiday false staleness:* `CDataQualityGuard::Evaluate` flagged `barAgeSeconds > periodSec * 3.0` as `QME_DQ_FLAG_STALE` without checking broker quote sessions. Fixed by waiving staleness only when `barAgeSeconds <= 7d` and `QmeGapCoveredByClosedQuoteSessions` confirms all missed bars fell outside open sessions (failing closed if unavailable).
  6. *Stop freeze-level & fast-path account refresh:* `CSymbolSpecifications::MinStopDistance` now takes `max(stopsLevelPoints, freezeLevelPoints) * point`; `CAccountContext::Refresh` fast path (`< 5s`) now refreshes terminal/MQL/connection flags and runs `RollDay`.
  7. *Strict persistence row parsing & multi-symbol resilience:* `CPositionStateStore::Deserialize` and `CSignalHistoryStore::Deserialize` reject malformed non-empty rows atomically; `CScanner::Init` skips unready individual symbols instead of failing `OnInit` if at least one symbol initializes; `QME_Main.mq5` `Housekeeping` tracks newest `snapshot.time` across all scanner symbols and forwards `g_engine.Errors()` to Watchdog/HealthMonitor, and guards `OnChartEvent` on `g_engine.Ready()`.
- **Verification:** `python3 test_system.py --verbose` -> `53/53` passed; `Tools/mql5check.py` 197 files 0 errors; `Tools/mql5fields.py` 0 suspicious accesses; `Tools/mql5calls.py` 0 arity mismatches; `git diff --check` clean. MetaEditor compilation and MT5 runtime/Strategy Tester execution remain `UNVERIFIED` in this Linux sandbox.

## QME-PROD-02 — Live MT5 DEMO log fixes (confluence calibration, BuildViews fallbacks, rejection spam suppression, preliminary score)
- **Branch:** `arena/62b247f8-qntum`.
- **Files:** `Strategy/SignalEngine.mqh`; `Core/Config.mqh`; `QME_Main.mq5`; `Tests/Integration/Test_MtfPipeline.mqh`; `test_system.py`; `QNTUM_CHANGELOG.md`.
- **Changes (Symptom -> Root Cause -> Fix):**
  1. *MTF confluence `0.00–0.12 < 0.40` locking out intraday setups:* `BuildViews` dropped `D1`/`H4`/`M15` direction when strict 3-EMA bias/trend stacks were transitioning, even when market structure (`HH/HL`, `LH/LL`, `MSS`, `BOS`) or `M5` displacement/pattern was directional; additionally, `D1` alone carries `47.8%` (`12.0/25.12`) of the 5-TF denominator, making `minConfluence=0.40` mathematically impossible whenever `D1` is neutral even with `InpRequireHtfAlignment=false`. Added conservative structure/event/displacement fallbacks in `CSignalEngine::BuildViews` (preserving all 5 configured slots) and calibrated default `minConfluence` / `InpMinConfluence` to `0.22`.
  2. *Duplicate rejected signal storm every 5s timer scan:* `CSignalEngine::Generate` previously suppressed repeat fingerprints only for `QME_REJ_INTERNAL`, creating new signal IDs and bloating `SignalRegistry`/`SignalHistoryStore` (~180 repeats per M15 bar) for deterministic `SetupGate`/`Entry`/`Score` rejections. Added a bounded 64-slot `(fingerprint, closedBarTime)` cache (`WasRejectedForClosedBars` / `RememberDeterministicReject`) so deterministic closed-bar rejections log once per closed M5/M15 bar while transient spread/staleness rejections still re-evaluate.
  3. *`score=0.0` logged on `SetupGate`-rejected signals:* `m_scorer.Score` previously ran only at Step 6 after `SetupGate`. Now `prelimScore` is populated before `SetupGate` (and recomputed with entry confirmation & penalties at Step 6) so rejected logs show the real factor score.
- **Verification:** `python3 test_system.py --verbose` -> `54/54` passed; `Tools/mql5check.py` 197 files 0 errors; `Tools/mql5fields.py` 0 suspicious accesses; `Tools/mql5calls.py` 0 arity mismatches; `git diff --check` clean. MetaEditor compilation and MT5 DEMO runtime re-test of the updated binary remain to be run by the operator on Windows/MT5.
