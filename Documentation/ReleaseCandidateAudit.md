## End-to-end code map (reviewed references are partial)
1. Inputs: `QME_Main.mq5::BuildInputs/OnInit` -> `Core/Config.mqh::QmeInputsDefaults/CConfig::Init`. Defaults observed: `analysisOnly=true`, DEMO=false, REAL=false, real arming=false, expected REAL login=0. MQL inputs are wired into the config aggregate.
2. Account: `Account/AccountContext.mqh` supplies snapshot; `Account/TradingPermissions.mqh::Authorize` checks account mode, REAL login, terminal/MQL/account/expert rights, symbol side/mode and directional config. `Runtime/RuntimeController.mqh::MayTrade` rechecks permissions and `Resume` lacks authorization arguments, so it cannot grant LIVE. **No expected broker-server input/check was found in inspected paths.**
3. Market/symbol: `Data/MarketData.mqh` owns per-symbol profiles, ticks, contexts, clock and sync; `Account/SymbolSpecifications.mqh` loads point/tick/contract/volume fields. Scanner refreshes all configured timeframes and records quality; `Runtime/Engine.mqh` applies data and causal gates before signal generation.
4. Time/history: `Data/BarSeries.mqh` requests closed bars beginning at CopyRates position 1; `Core/HistoryGuard.mqh` checks descending order/gaps; `Data/QuoteSessions.mqh` uses the recurring weekly `SymbolInfoSessionQuote` schedule. It cannot prove past holidays or DST schedule changes; unknown schedules should fail closed. The XAU D1 Apr 3 holiday remains blocked pending historical evidence.
5. Signal: `Strategy/MTF/CandidateCollector.mqh` builds hypotheses and sets `h.valid` after zone/entry validation. `CandidateClusterer::Merge` merges valid hypotheses/evidence, `SetupEngine::Evaluate` gates `mc.valid`, `SignalEngine::BuildViews/Generate` forms confluence then setup, entry confirmation and scoring. `Intelligence/MtfConfluenceEngine.mqh` computes `sum(weight*strength for aligned views)/sum(weight)`; per weights: M5=1, M15=sqrt(3), H1=sqrt(12), H4=sqrt(48), D1 capped at 12. Neutral supplied views add denominator weight, no numerator.
6. Decisions and execution: Engine passes approved signals to `Strategy/DecisionEngine.mqh`, then `Risk/RiskEngine.mqh` and `Risk/PreTradeValidator.mqh`; `Execution/TradeRequestBuilder.mqh` forms request and `Execution/ExecutionGateway.mqh` authorizes/idempotently checkpoints/sends. `OnTradeTransaction` dispatches through Engine/transaction handler. A decision/approval/order send is not a fill; broker transactions and position reconciliation establish fills/positions.
7. Management and state: Engine timer performs reconciliation and position management independently of new signal flow; shutdown checkpoints, reports protection, releases gateway/risk/scanner/data/account. `Persistence/StateRecovery.mqh` composes/restores state. A newly confirmed state-file scope defect is fixed on this branch (see below), but restart/crash/multi-instance behavior is NOT VERIFIED.

## Observations and arithmetic
- Supplied EURUSD/GBPUSD/USDJPY values 0.12, 0.39, 0.00, 0.19, 0.28, 0.01 are below configured `minConfluence=0.40`; preserve NO_CONFLUENCE rejection. The code formula and timeframe weights above match the intended weighted fraction. Exact per-log arithmetic cannot be recomputed because the logs do not include each view's timeframe, direction, strength, or timestamps.
- A defect was found in `SignalEngine::BuildViews`: invalid/missing evidence views were omitted from the input array, while the MTF engine's contract says a missing/undecided view retains denominator weight. Omitting missing views can inflate scores. This branch now emits all five role slots with neutral/zero strength when evidence is invalid; denominator is stable and stricter, no threshold is lowered. A deterministic formula test was added.
- USDJPY “analysis invalid” cannot be diagnosed from that phrase alone. Scanner data quality, analysis module validity, and Engine causal coherence are separate gates; no associated raw snapshot/timestamps were supplied. NOT REPRODUCED.
- Prior FX weekend gaps: quote sessions are recurring weekly schedules, not a historical calendar. The test fixtures and current evaluator cover synthetic weekly windows, but DST, broker server offset transitions, actual historical gold sessions, and account-specific quote schedules are NOT VERIFIED. Unknown historical sessions fail closed.
- Tick freshness uses `MqlTick.time` seconds compared with `TimeTradeServer`; `time_msc` is used to reject a backward tick update. Startup warm-up and quiet-market broker behavior remain NOT VERIFIED on an actual feed.
- GBPUSD spread values are broker points; historical bar spread averages may be zero/rounded. Execution risk guard also checks configured absolute point cap (zero disables) and spread/ATR. Existing logs' 2.0 vs displayed 0.4 indicates abnormal ratio; do not waive it. Exact ratio requires unrounded tick/bar series. NOT REPRODUCED.
- QATS is a separate EA; QME's pre-trade validator refuses new entries when it detects foreign positions or any active account order, but this conservative path has not been tested concurrently with QATS/manual activity.

## Compatibility and operator procedure (provisional, not an approval)
| Dimension | Status |
|---|---|
| Account mode | ANALYSIS default. Demo tests only after operator separately enables an isolated DEMO config. Real and arming switches remain false. |
| Broker/server | Not certified. Requires exact server-specific symbol sessions, symbol specs, retcodes, execution mode, and holiday evidence. |
| FX / metals | Formula unit tests only; actual tick values, currencies and volume minima must be verified per symbol. |
| Netting / hedging | NOT VERIFIED as a supported matrix. No claim of compatibility. |
| Other EAs/manual | Validator refuses when foreign positions or account orders are detected; concurrent QATS case NOT VERIFIED. |

Runbook if an operator later performs DEMO-only validation: verify account banner says DEMO and `analysisOnly`/switches match the intended test; start analysis-only first; inspect symbol/timeframe validity, latest causal/data gate and signal stage counters; compare broker quote schedules and history; only then do isolated DEMO tests. Any unknown intent, state namespace collision/legacy state, position without SL, mismatch or disconnect means stop NEW entries, leave transaction/reconciliation/monitoring paths active, alert the operator and reconcile with broker terminal before restart. Do not auto-resume a FAULT. Kill switch: disable AutoTrading and pause/stop EA; manually verify all active orders/positions and SL/TP with the broker; never assume EA shutdown closes exposure. Recovery: preserve state files, identify exact login/server/magic namespace, reconcile every broker deal/order/position, resolve in-flight intent manually, then operator-controlled reinitialization. Rollback: disable EA/AutoTrading, preserve logs/checkpoints, deploy prior reviewed binary only after reconciling all existing positions; do not delete state files as a rollback shortcut.
